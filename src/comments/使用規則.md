# 評論介面卡使用規則

本目錄是 CitrusGrid 的評論介面卡目錄。站點主體不內建任何評論系統，只提供一套統一的瀏覽器端評論介面；具體評論能力由本目錄下的介面卡（每個評論系統一個獨立 ts 檔案）提供，類似換插頭：把介面卡放進本目錄、在 `site.config.ts` 裡填上介面卡名即完成接入，站點主體只依賴介面，不依賴任何具體評論系統。

## 一、啟用與停用

在站點唯一配置源 `src/site.config.ts` 中：

```ts
// 評論介面卡名（不含副檔名），對應本目錄下的 <介面卡名>.ts
commentScript: 'utterances',  // 啟用：使用 src/comments/utterances.ts
commentScript: '',            // 停用（預設）：不渲染評論區，不注入指令碼，不發任何請求
```

規則：

- 值為介面卡檔名（不含 `.ts` 字尾），如 `utterances`；
- 留空則完全停用：頁面不渲染評論區、瀏覽器不載入評論執行時、不發任何請求；
- 介面卡名不合法或檔案不存在時不會報錯，只會輸出控制台警告並按停用處理；
- 評論系統的私有配置（如 utterances 的 repo）**不寫在 site.config.ts**，寫在對應介面卡 ts 檔案頂部的配置區（見第五節）。

## 二、目錄結構

```text
src/comments/
├── client.ts          # 框架客戶端執行時（勿動）：懶載入排程、介面卡載入、佔位狀態機、主題轉發
├── utterances.ts      # 介面卡：utterances（GitHub Issues 評論），檔案頂部為配置區
└── 使用規則.md         # 本檔案
```

## 三、執行機制（框架側 client.ts 保證）

| 機制 | 說明 |
| --- | --- |
| 懶載入 | 評論區掛載點由 IntersectionObserver 監聽，臨近視口（提前 300px）才載入介面卡；評論位於首屏之下時首屏完全不請求評論資源。不支援 IntersectionObserver 的環境降級為立即載入 |
| 程式碼拆分 | `import.meta.glob` 讓每個介面卡成為獨立 chunk，只拉取 site.config.ts 指名的那一個；介面卡模組會話級快取，Swup 換頁不重複拉取 |
| 預留佔位 | 評論區由服務端渲染（最小高度 + shimmer 骨架），介面卡渲染出首個內容節點後撤掉骨架，載入全程無佈局跳動 |
| 非同步載入 | 介面卡 chunk 與第三方指令碼（如 utteranc.es/client.js）均為非同步注入，不阻塞頁面 |
| 主題同步 | 執行時監聽全域性 `theme-change` 事件並轉發給介面卡的 `onThemeChange`，介面卡自行同步給評論元件 |
| 換頁相容 | 每次頁面載入（首次整頁 + Swup 導航）都會重新執行掛載流程；換頁銷燬舊評論區前會呼叫介面卡的 `unmountComment`（若匯出） |
| 失敗降級 | 介面卡載入失敗、未匯出 `mountComment` 或掛載拋錯：控制台輸出警告，整個評論區隱藏（`is-error`），頁面其餘部分不受影響 |

預載距離與骨架兜底超時是 client.ts 頂部的常量（`LOAD_MARGIN` / `SKELETON_TIMEOUT`），可按需調整。

## 四、介面卡介面契約（必須遵守）

介面卡是一個普通的 TypeScript 模組，通過命名匯出向執行時提供以下函式（不需要預設匯出）。介面卡執行在瀏覽器端，不要使用 Node 專有 API：

### 1. `mountComment(container)` —— 掛載評論（必選）

```ts
export function mountComment(container: HTMLElement): void | Promise<void>
```

- `container` 是評論掛載容器（評論區 `<section>` 內的 `.comment-mount` 空元素），把評論元件渲染進去即可；
- 配置不完整（如必填項為空）應直接拋錯，由執行時統一隱藏評論區並輸出警告；
- 應儘快返回（如只負責注入第三方引導指令碼），第三方指令碼的後續載入渲染由評論系統自行處理；
- 重入安全由執行時兜底（每次換頁都是新容器），介面卡無需自行去重。

### 2. `onThemeChange(dark)` —— 主題切換（可選）

```ts
export function onThemeChange(dark: boolean): void
```

- 執行時監聽全域性 `theme-change` 事件後轉發，`dark` 為 `true` 表示切換到深色；
- 初始主題不經過此函式：`mountComment` 執行時應按當前主題（`document.documentElement.classList.contains('dark')`）自行初始化；
- 若評論元件不支援主題，不匯出即可。

### 3. `unmountComment()` —— 換頁清理（可選）

```ts
export function unmountComment(): void
```

- Swup 換頁、評論區即將隨舊 DOM 銷燬前呼叫，用於清理定時器、全域性監聽器等；大多數介面卡無需匯出。

### 4. 錯誤處理約定（重要）

- 配置缺失、載入失敗、掛載失敗等情況應丟擲異常，由執行時統一捕獲後隱藏整個評論區；
- 不要用返回 `null` 等方式表達失敗，直接 throw 即可。

## 五、配置區約定

各評論系統的私有配置寫在介面卡 ts 檔案頂部的配置區，**不進 site.config.ts**：site.config.ts 的評論配置只負責「用哪個介面卡」，即只有介面卡檔名一項。配置區的欄位命名與預設值由介面卡自行定義，註釋須寫清每個欄位的含義與填寫方法。

## 六、頁面掛載點（框架自動處理，介面卡作者無需關心）

啟用後 `src/components/Comments.astro` 在頁面渲染評論區掛載點，client.ts 完成剩餘工作：

| 掛載點 | 位置 | 結構 |
| --- | --- | --- |
| `<section data-comment-script="介面卡名">` | PostPage 文末、FriendsPage 文末 | 內含 `.comment-skeleton` 骨架與 `.comment-mount` 掛載容器 |

骨架在掛載容器出現首個非 `script` 子節點（即評論元件真實內容）後移除，8 秒超時兜底強制移除，防止骨架卡死。

## 七、編寫你自己的介面卡（示例骨架）

以 giscus 為例，新建 `src/comments/giscus.ts`，再在 site.config.ts 填 `commentScript: 'giscus'` 即完成接入：

```ts
// src/comments/giscus.ts —— site.config.ts 填 commentScript: 'giscus' 即啟用

// ========== 配置區 ==========
const config = {
  repo: '',
  repoId: '',
  category: '',
  categoryId: '',
  lightTheme: 'light',
  darkTheme: 'dark',
}
// ============================

const isDark = () => document.documentElement.classList.contains('dark')

export function mountComment(container: HTMLElement): void {
  if (!config.repo) throw new Error('[comments] giscus.repo 未配置')
  const script = document.createElement('script')
  script.src = 'https://giscus.app/client.js'
  script.async = true
  script.setAttribute('data-repo', config.repo)
  // ...其餘 data-* 屬性
  script.setAttribute('data-theme', isDark() ? config.darkTheme : config.lightTheme)
  container.appendChild(script)
}

export function onThemeChange(dark: boolean): void {
  document.querySelector<HTMLIFrameElement>('iframe.giscus-frame')?.contentWindow?.postMessage(
    { giscus: { setConfig: { theme: dark ? config.darkTheme : config.lightTheme } } },
    'https://giscus.app',
  )
}
```

注意事項：

1. `mountComment` 必選，`onThemeChange` / `unmountComment` 可選，只匯出你需要的；
2. 介面卡只在瀏覽器端執行，不會在構建期執行，停用時也不會被打包；
3. 介面卡匯出的一切都會打進瀏覽器 chunk，注意不要在配置區嵌入金鑰等敏感憑證（評論系統所需的一般都是公開值）；
4. 檔名即介面卡名，建議與評論系統同名（如 `giscus.ts`、`waline.ts`）。
