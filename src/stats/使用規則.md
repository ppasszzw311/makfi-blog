# 統計指令碼（外掛）使用規則

本目錄是 CitrusGrid 的統計外掛目錄。站點本身不內建任何統計服務，只提供一套瀏覽器端注入介面；統計能力由本目錄下的指令碼（外掛）提供，類似外掛機制：把指令碼放進本目錄、在 `site.config.ts` 裡填上指令碼名即完成接入。

## 一、啟用與停用

在站點唯一配置源 `src/site.config.ts` 中：

```ts
// 統計指令碼名（不含副檔名），對應本目錄下的 <指令碼名>.ts
statsScript: 'visitor-stats',  // 啟用：載入 src/stats/visitor-stats.ts
statsScript: '',               // 停用（預設）：不注入任何指令碼，頁面無統計掛載點，也不發統計請求
```

規則：

- 值為指令碼檔名（不含 `.ts` 字尾），如 `visitor-stats`；
- 留空（預設）則完全停用：頁面不渲染統計掛載點、瀏覽器不載入統計客戶端、不發任何請求；
- 指令碼名不合法或檔案不存在時不會報錯，只會輸出控制台警告並按停用處理；
- 數字在瀏覽器端即時獲取，每次頁面載入（含 Swup 換頁）都會重新整理，無需重新構建部署。

## 二、目錄結構

```text
src/stats/
├── client.ts          # 框架客戶端執行時（勿動）：收集掛載點、快取、限速、填充數字
├── visitor-stats.ts   # 示例外掛：Cloudflare Worker 統計服務實現
└── 使用規則.md         # 本檔案
```

## 三、執行機制（框架側 client.ts 保證）

| 機制 | 說明 |
| --- | --- |
| 埋點上報 | 外掛匯出 `trackVisit` 時，客戶端在每次頁面載入（首次整頁 + Swup 導航）呼叫一次，向統計服務記錄一次訪問（fire-and-forget，不快取、不限速） |
| 注入時機 | `site.config.ts` 啟用時 BaseLayout 注入客戶端執行時（僅生產環境，dev 自動不注入不發請求）；每次頁面載入（首次整頁 + Swup 導航）收集當前頁掛載點並填充 |
| 快取 | sessionStorage + TTL（生產 5 分鐘 / dev 1 分鐘）：同一瀏覽器會話內重複訪問/換頁不重複請求；成功與失敗都會快取（失敗為負快取，TTL 內不重試，避免重新整理時反覆請求失敗的介面） |
| 全站複用 | `getArticleStats` 響應附帶 `siteTotal`/`siteUnique` 欄位時直接複用，省掉 `/total` 請求（文章頁通常 1 個請求即可同時滿足文章 + 全站兩處顯示） |
| 速率限制 | 序列佇列 + 相鄰請求最小間隔 150ms；外掛側可再做收斂（如 visitor-stats 統一走 `/total` + 外掛內 TTL 快取/in-flight 去重），任意頁面每輪至多 1 個統計請求 |
| 失敗降級 | 外掛拋錯 / 請求失敗：對應掛載點保留「-」佔位，控制台僅輸出警告 |

TTL 與請求間隔是 client.ts 頂部的常量（`CACHE_TTL` / `REQUEST_GAP`），可按需調整。

## 四、外掛介面契約（必須遵守）

外掛是一個普通的 TypeScript 模組，通過命名匯出向客戶端提供以下可選函式（不需要預設匯出）。指令碼執行在瀏覽器端，可以使用 `fetch`，不要使用 Node 專有 API：

### 1. `getSiteTotal()` —— 全站累計（可選）

```ts
export function getSiteTotal(): Promise<{
  siteTotal: number        // 全站累計 PV（訪問次數）
  siteUnique: number       // 全站累計 UV（獨立訪客數）
}>
```

- 渲染位置：個人名片統計卡片（ProfileCard），與「部落格總篇數」並列。
- 若不匯出此函式，名片不顯示全站統計，不影響其他功能。

### 2. `getArticleStats(path)` —— 單篇文章累計（可選）

```ts
export function getArticleStats(path: string): Promise<{
  articleTotal: number     // 文章累計 PV（閱讀次數）
  articleUnique: number    // 文章累計 UV（獨立閱讀數）
  siteTotal?: number       // 可選：附帶的全站 PV（提供則免去 /total 請求）
  siteUnique?: number      // 可選：附帶的全站 UV
}>
```

- `path` 入參為文章頁規範路徑，如 `/posts/hello-world`（與語言字首無關，固定以 `/posts/` 開頭）。外掛內部可自行做更寬鬆的規範化，但必須保證能處理 `/posts/xxx` 這種標準形式。
- 渲染位置：文章卡片「前往閱讀」徽標左側（列表頁）、文章閱讀頁頭部「閱讀時間」之後。列表頁多篇徽標的查詢由外掛統一收斂到單次請求（如 visitor-stats 全部走 `/total` 並做外掛內 TTL 快取 + in-flight 去重），不會逐篇請求打爆統計服務。
- 建議：優先提供一次返回全量資料的介面（如 visitor-stats 的 `/total`，全站 + 全部文章列表一次拿齊）；或介面順帶返回全站資料（客戶端會自動複用），把每頁請求數壓到最低。

### 3. `trackVisit(path?)` —— 訪問埋點上報（可選）

```ts
export function trackVisit(path?: string): void
```

- 客戶端在每次頁面載入（首次整頁 + Swup 導航）時呼叫一次，用於向統計服務記錄一次訪問（PV 埋點）。不快取、不限速——每次真實訪問都應上報；
- `path` 入參為當前頁面路徑（`location.pathname`），外掛可忽略該引數自行取值；
- 實現必須 fire-and-forget：內部吞掉所有錯誤（如 `fetch(...).catch(() => {})`），不得向頁面拋異常；
- 若不匯出此函式，客戶端跳過埋點，數字展示不受影響。

### 4. 錯誤處理約定（重要）

- 請求失敗、服務不可達等情況應丟擲異常（reject），由客戶端統一捕獲後隱藏對應統計；
- 不要用返回 `-1`、`null` 等方式表達失敗，直接 throw 即可。

## 五、頁面掛載點（框架自動處理，外掛作者無需關心）

啟用後元件渲染 `data-stats` 掛載點，由 client.ts 填充：

| 掛載點 | 位置 | 填充內容 |
| --- | --- | --- |
| `data-stats="site-pv"` / `"site-uv"` | ProfileCard | 全站累計 PV / UV |
| `data-stats="article-pv"` / `"article-uv"`（所在容器帶 `data-stats-path="/posts/xxx"`） | PostCard 徽標、PostPage 頭部 | 文章累計 PV / UV |

掛載點啟用即隨頁面渲染（初始佔位「-」），客戶端獲取成功填充數字，失敗保留「-」。

## 六、編寫你自己的外掛（示例骨架）

```ts
// src/stats/my-stats.ts —— site.config.ts 填 statsScript: 'my-stats' 即啟用

export function trackVisit(path: string = location.pathname) {
  // fire-and-forget：失敗靜默，不影響頁面
  fetch(`https://your-api.example/log?path=${encodeURIComponent(path)}`).catch(() => {})
}

export function getSiteTotal() {
  return fetch('https://your-api.example/site')
    .then((r) => r.json())
    .then((d) => ({ siteTotal: d.views, siteUnique: d.visitors }))
}

export function getArticleStats(path: string) {
  return fetch(`https://your-api.example/page?path=${encodeURIComponent(path)}`)
    .then((r) => r.json())
    .then((d) => ({
      articleTotal: d.views,
      articleUnique: d.visitors,
      siteTotal: d.siteViews,      // 可選，能帶就帶
      siteUnique: d.siteVisitors,  // 可選
    }))
}
```

注意事項：

1. 三個函式都是可選的，只匯出你需要的那些；
2. 指令碼只在瀏覽器端執行，不會在構建期執行，也不會在停用時被打包；
3. 外掛可以額外匯出僅供服務端使用的輔助函式（如 visitor-stats 的 `getRealtimeStats`），客戶端只調用上述三個契約函式，其餘匯出會被一併打進瀏覽器包，注意不要在其中嵌入金鑰等敏感憑證；
4. 建議服務端介面帶短快取（如 60s），配合客戶端 TTL 快取把請求量降到最低。
